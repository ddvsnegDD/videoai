# ROADMAP.md — VideoAI

План разработки MVP. Каждый спринт — это законченная веха, после которой можно показать прогресс.

---

## Спринт 0: фундамент (3-4 дня)

**Цель:** работающий проект на Railway с пустым кабинетом и лендингом.

- [ ] `npm create vite@latest videoai -- --template react`
- [ ] Структура папок по `CLAUDE.md`
- [ ] `theme.js` с палитрой `C` (изумрудный)
- [ ] `global.css` (reset + base + layout + buttons + cards)
- [ ] `Layout.jsx` (Header + Footer)
- [ ] `Btn.jsx` (primary/dark/outline)
- [ ] `App.jsx` с маршрутами
- [ ] `HomePage.jsx` — лендинг (hero + 3 фичи + тарифы + FAQ + CTA)
- [ ] Подключить Manrope + Inter из Google Fonts
- [ ] GitHub-репозиторий, первый коммит
- [ ] Railway: проект + PostgreSQL
- [ ] `server.js` с `/api/health`, статика `dist/`
- [ ] Деплой работает: открывается лендинг, `/api/health` отвечает

**Definition of Done:** прод-URL открывается, лендинг выглядит как готовый продукт.

## Спринт 1: авторизация и кабинет (3-4 дня)

**Цель:** пользователь может зарегистрироваться, войти, увидеть свой пустой кабинет.

- [ ] `server/db.js` — таблицы `users`, `auth_codes`
- [ ] `server/email.js` — Brevo (верификация домена)
- [ ] `server/auth.js` — генерация кода, отправка, проверка, JWT
- [ ] API: `POST /api/auth/send-code`, `POST /api/auth/verify`, `GET /api/auth/me`, `POST /api/auth/logout`
- [ ] `LoginPage.jsx` — двухшаговая форма (email → код)
- [ ] `AuthProvider` + хук `useAuth()`
- [ ] Защищённые маршруты (редирект на `/login` если нет JWT)
- [ ] `DashboardPage.jsx` — пустое состояние "Создайте первый проект"
- [ ] Начисление 30 бесплатных кредитов при регистрации
- [ ] Header показывает email и баланс кредитов

**DoD:** можно пройти полный путь: ввёл email → получил код на почту → вошёл в кабинет → видишь свой баланс.

## Спринт 2: первый AI-эндпоинт и движок задач (4-5 дней)

**Цель:** работает генерация сценариев через GigaChat с polling-моделью.

- [ ] Регистрация в Сбер AI Studio, получение `GIGACHAT_CLIENT_ID`/`SECRET`
- [ ] `server/providers/llm.js` — обёртка над GigaChat API (auth-токен, чат, обработка ошибок)
- [ ] `server/prompts/scenario.js` — промпт для генерации 3 вариантов сценария
- [ ] `server/db.js` — таблица `generation_jobs`, `projects`
- [ ] `server/jobs.js` — диспетчер: создание задачи, фоновое выполнение через `setImmediate`, обновление статуса
- [ ] API: `POST /api/jobs`, `GET /api/jobs/:id`, `GET /api/jobs?project_id=...`
- [ ] API: `POST /api/projects`, `GET /api/projects`, `GET /api/projects/:id`
- [ ] Фронт: хук `useJobPolling(jobId)`
- [ ] `EditorPage.jsx` — шаг 1: ввод темы → запуск задачи → отображение прогресса → 3 варианта сценария
- [ ] Списание кредитов после успешной генерации
- [ ] Карточки проектов в `DashboardPage`

**DoD:** пользователь вводит "тыквенный латте, осень, кофейня" → через 5-10 секунд видит 3 варианта сценария → выбирает один → проект сохранён.

## Спринт 3: визуал и озвучка (5-6 дней)

**Цель:** AI генерирует картинки и озвучивает сценарий.

- [ ] `server/providers/image.js` — Kandinsky API (через GigaChat Image или прямой)
- [ ] `server/providers/tts.js` — Yandex SpeechKit (синтез речи)
- [ ] `server/storage.js` — Yandex Object Storage (загрузка, выдача подписанных URL)
- [ ] Создать бакет `videoai-media` в Yandex Cloud
- [ ] Расширение `generation_jobs`: типы `image`, `tts`
- [ ] Логика "сценарий → раскадровка": разбиваем сценарий на 3-5 сцен, для каждой генерим картинку + озвучку
- [ ] `EditorPage.jsx` — шаг 2: предпросмотр сцен (картинка + кнопка "переслушать озвучку")
- [ ] Возможность перегенерировать отдельную сцену
- [ ] `src/data/voices.js` — список голосов SpeechKit
- [ ] Выбор голоса перед генерацией

**DoD:** пользователь видит готовую раскадровку из 4 сцен — каждая с картинкой и голосом, может перегенерить любую.

## Спринт 4: монтаж видео (FFmpeg) (5-7 дней)

**Цель:** из сцен собирается итоговый видеоролик.

- [ ] Установить FFmpeg на Railway (через Nixpacks или buildpack)
- [ ] `server/providers/editor.js` — обёртка над FFmpeg
- [ ] `src/data/templates.js` — 5 базовых шаблонов: 
  1. "Анонс товара" (логотип → продукт → цена → CTA)
  2. "Цитата дня" (изображение + текст крупно + музыка)
  3. "До/После" (split-экран)
  4. "Сторителлинг" (3 сцены подряд с озвучкой)
  5. "Карусель-факты" (несколько слайдов с текстом)
- [ ] Каждый шаблон — это набор инструкций для FFmpeg (длительности, переходы, текстовые оверлеи)
- [ ] Тип задачи `compose` — финальный монтаж
- [ ] Сохранение итогового MP4 в S3
- [ ] `VideoPreview.jsx` — плеер с итоговым видео
- [ ] Кнопка "Скачать"

**DoD:** пользователь нажимает "Собрать видео" → через 1-2 минуты получает готовый MP4 в формате 9:16 длительностью 15-30 сек.

## Спринт 5: публикация в VK и Telegram (4-5 дней)

**Цель:** готовое видео публикуется в соцсети.

- [ ] VK App: регистрация, OAuth, scopes `wall,video,groups,offline`
- [ ] Telegram Bot: создание через BotFather, инструкция пользователю как добавить бота в канал админом
- [ ] `server/db.js` — таблица `social_connections`, шифрование токенов
- [ ] `server/providers/vk.js` — OAuth-callback, `video.save`, `video.upload`, `wall.post`
- [ ] `server/providers/telegram.js` — `sendVideo` в канал
- [ ] `server/providers/max.js` — заглушка, возвращает "MAX скоро" 
- [ ] API: `GET /api/social/vk/auth`, `GET /api/social/vk/callback`, `POST /api/social/telegram/connect`, `GET /api/social/connections`
- [ ] API: `POST /api/publications` (создаёт публикацию, публикует сразу)
- [ ] `SocialConnector.jsx` — список подключений и кнопки "Подключить"
- [ ] `PublishPage.jsx` — выбор каналов + текст поста + кнопка "Опубликовать"
- [ ] Таблица `publications` с историей

**DoD:** пользователь подключает VK-группу → выбирает её → жмёт "Опубликовать" → пост с видео появляется в VK.

- [ ] API: `POST /api/payments` (создать платёж), `POST /api/payments/yookassa-webhook`
- [ ] `src/data/tariffs.js` — 3 тарифа
- [ ] `BillingPage.jsx` — карточки тарифов + история платежей
- [ ] Начисление кредитов после успешного платежа
- [ ] Email-уведомление о покупке
- [ ] Обработка возвратов (через админку, ручная процедура)

**DoD:** пользователь покупает тариф "Старт" → платит → получает 500 кредитов → видит в истории платежей.

## Спринт 7: админка и предпродакшн (3-4 дня)

**Цель:** мы можем управлять сервисом и видеть метрики.

- [ ] `AdminPage.jsx` — защищён `ADMIN_PASSWORD`
- [ ] Таблицы: пользователи (поиск, начисление кредитов вручную), задачи (статусы, ошибки), платежи
- [ ] Метрики: DAU, конверсия, средняя длительность задачи, количество ошибок по провайдерам
- [ ] Алёрты в Telegram-бот при failed-задачах > порога
- [ ] Логирование ошибок (Sentry или просто в БД)
- [ ] Документация для пользователей (FAQ-блок на лендинге)
- [ ] Политика конфиденциальности, оферта (текст готовим в Notion, ставим на сайт)
- [ ] Прохождение полного пути от регистрации до публикации — 5 раз без багов

**DoD:** мы готовы дать ссылку 50 пользователям и не сгореть.

## После MVP — что приоритетно

1. **Планировщик публикаций** (отложенный постинг)
2. **MAX API** (когда станет публичным)
3. **Команды** (несколько пользователей на одном кабинете) — B2B-фаза
4. **Бренд-киты** (логотип, фирменные цвета, шрифты применяются автоматически)
5. **Расширенная аналитика** (статистика публикаций из API соцсетей)
6. **Свои аватары и липсинк** (отдельный большой проект)

## Оценка по времени

При работе одного разработчика с Claude Code в режиме 4-6 часов в день:
- Спринты 0-2: ~2 недели — у тебя работает кабинет с генерацией сценариев
- Спринты 3-4: ~3 недели — есть готовые видео
- Спринты 5-7: ~2 недели — есть публикация и биллинг

**Итого до MVP: ~7-8 недель** при условии отсутствия больших технических сюрпризов (особенно с FFmpeg на Railway и квотами VK API).
