### Параметры запроса (микрофикс применён — сверено с доками fal)
Параметры задаются **по-модельно** (имена полей у Wan и Veo разные). Финальный `input` логируется перед submit (`[fal] Submit input`).

**Wan 2.7** (`fal-ai/wan/v2.7/image-to-video`):
```js
{
  image_url, prompt,
  resolution: '720p',                // enum: 720p / 1080p
  duration: 5,                       // на практике принимается ЧИСЛОМ (не строкой); enum "2"–"15"
  negative_prompt: '...',            // до 500 символов; СЕЙЧАС там 'text overlay' — неверно, см. находки
  enable_prompt_expansion: false     // fal не переписывает наш промпт
}
```
Аудио: у Wan **нет** `generate_audio` — звук подаётся только через `audio_url` (не передаём), т.е. видео без звука by design.

**Veo 3.1 fast** (`fal-ai/veo3.1/fast/image-to-video`):
```js
{
  image_url, prompt,
  resolution: '720p',                // enum: 720p / 1080p / 4k
  duration: '8s',                    // СТРОКА С СУФФИКСОМ, enum "4s"/"6s"/"8s"
  generate_audio: false,             // ПО УМОЛЧАНИЮ true — без этого ~×2 дороже!
  aspect_ratio: '9:16',              // вертикаль под соцсети
  negative_prompt: '...'
}
```

**Ключевые отличия полей:** длительность — Wan `"5"` без суффикса / Veo `"8s"` с суффиксом; аудио — у Wan параметра нет / у Veo нужен явный `generate_audio: false`; пропорции — только у Veo (`aspect_ratio`), Wan наследует формат исходного фото.

**Проверено в живом тесте (Wan):** 716×1284 (~720p, по аспекту фото), 5.0 c, `duration` числом сработало. **У Wan есть пустая (молчаливая) аудиодорожка** — не «нет потока». **Не проверено:** Veo вообще; форс `aspect_ratio: '9:16'` на не-вертикальном фото (может обрезать товар).

### Асинхронный паттерн
Реализован свой polling, НЕ вебхуки:
1. `fal.queue.submit(modelId, { input })` → получаем `request_id`
2. Цикл: `fal.queue.status(modelId, { requestId })` каждые 5 сек
3. При `COMPLETED`: `fal.queue.result(modelId, { requestId })` → достаём video URL
4. Скачиваем видео (`fetch(videoUrl)`) → перезаливаем в наш S3 (`uploadBuffer`)

Таймаут: 5 минут. При `FAILED` — немедленная ошибка.

### Парсинг ответа fal
Пробуем три варианта: `data.video.url` → `data.output.url` → `data.url`. Если ни один не сработает — ошибка с логированием raw response.

### Картинка как публичный URL
Фото загружается в наш S3: `uploads/{userId}/{timestamp}.jpg`. URL формата `https://videoai-media.storage.yandexcloud.net/uploads/...`. Бакет настроен на публичное чтение. fal должен принять этот URL. **Не проверено живьём.**

## Живой тест Wan — результаты и находки (история; эконом-модель заменена на Kling, см. выше)

Тест на реальном фото товара (флакон крема AURA с золотой крышкой и текстом на корпусе).

### Технические замеры (ffprobe готового MP4)
- Разрешение **716×1284** — это ~720p, но размер следует пропорциям исходного фото (не ровно 720×1280). Wan наследует аспект картинки.
- Длительность ровно **5.0 c**; `duration` ушло **числом** `5` и сработало.
- **У Wan ЕСТЬ молчаливая аудиодорожка** (AAC, ~−55 dB ≈ тишина). То есть «нет аудиопотока» — НЕВЕРНО для Wan: дорожка есть, но пустая. (У Veo при `generate_audio:false` дорожки нет совсем.) Проверку через ffprobe скорректировать: у Wan смотреть уровень звука, не наличие потока.
- Эндпоинт в коде зовётся `fal-ai/wan-27-i2v` (в счёте/доках — `fal-ai/wan/v2.7/image-to-video`). Это псевдонимы одной модели; свести к одному написанию.

### Главная находка — лотерея сида (предсказуемость)
`seed` во входе **не задавался** → fal брал случайный → один и тот же промпт давал разный результат. 6 запусков = 6 разных сидов = разное движение:
- часть сидов → лёгкое движение, текст бренда сохраняется;
- часть сидов → банку разворачивает «как вентилятор», текст уходит за бок и плывёт.
Надёжность при текущих настройках ~50%. **Это блокер для платного продукта** и главная причина внедрения фикса сида (ниже).

### Читаемость текста
- На «удачных» сидах «AURA» и «Luminous Radiance Cream» читаемы; мельчайшая строка (состав/объём) плывёт; даже в лучших «50ml» превратилось в «30ml».
- Вывод: тезис «текст переживает движение» **достижим**, но на эконом-модели (Wan) ненадёжен для мелкого шрифта и ломается при сильном движении.
- `negative_prompt` сейчас = `low quality, distortion, warping, blurry, text overlay`. `text overlay` бьёт мимо (это про «не добавлять новый текст», а не «сохранить существующий»). Заменить на целевой: `warped text, distorted lettering, deformed logo, smeared label, illegible text`.
- Промпты пресетов движения переписаны (убрать `rotation`, держать товар лицом к камере, ограничить амплитуду) — **в код пока НЕ внесены** (отложено), хранятся отдельно.

### Экономика — подтверждена счётом
Реальные списания: Wan **$0.50/ролик** (5 сек × $0.10), Veo **$1.20/ролик** (8 сек × $0.15). Совпадает с заложенными ~70 ₽ / ~160 ₽ при браке ×1.5. `generate_audio:false` у Veo подтверждается ставкой (без удвоения за звук).

## Денежная утечка — обнаружение и фикс

### Проблема
fal списывает за **фактически выполненный** запрос независимо от того, забрало ли приложение результат. Зависшие поллинги (Wan идёт 4-5 мин, приложение сдавалось по таймауту), повторные клики «Создать» и ретраи → **6 оплаченных генераций Wan ($3) при одной нужной**. Подтверждено счётом (30 сек = 6 роликов на серверном ключе). В счёте видно два ключа: `key=...` (серверный `FAL_KEY` = сайт) и `workos=user_...` (дашборд/песочница — ручные тесты).

### Фикс — реализован (5 слоёв)
| Слой | Что сделано |
|---|---|
| 2.1 Дедуп | Фронт: guard `creating` + проверка в `handleCreate`. Бэк: проверка активной задачи (user+project) + `idempotency_key` + partial UNIQUE индекс `uniq_active_job` |
| 2.2 request_id | `fal_request_id` сохраняется СРАЗУ после `fal.queue.submit`, ДО поллинга; при обрыве reconciler возобновляет по нему, не пере-сабмитит |
| 2.3 refund≠timeout | По `POLL_TIMEOUT` — НЕ рефандим, оставляем `running` для reconciler. По `FAL_FAILED` — рефандим. Флаг `refunded` против двойного возврата |
| 2.4 Reconciler | `startReconciler()` каждые 90 c опрашивает «осиротевшие» задачи по `fal_request_id`, финализирует (COMPLETED→S3→done, FAILED→refund). **Дополнительно:** 404 от fal теперь трактуется как terminal failure (коммит `1091d13`) |
| 2.5 Предохранитель | `MAX_CONCURRENT_JOBS_PER_USER = 2`, ошибка `TOO_MANY_ACTIVE_JOBS` |

**Watchdog переработан:** убивает только задачи БЕЗ `fal_request_id` (не дошедшие до submit); задачи С `fal_request_id` ведёт reconciler. Конфликта между ними нет.

### Проверка (без денег — тесты B/C/D, все PASS)
- **A. Схема на проде** — PASS. Колонки `seed`, `fal_request_id`, `last_polled_at`, `idempotency_key`, `refunded` есть; индекс `uniq_active_job ON (idempotency_key) WHERE status IN ('pending','running') AND idempotency_key IS NOT NULL`. Всего 17 колонок.
- **B. Дедуп** — PASS. Две вставки с одним `idempotency_key` и `status='pending'` → вторая отклонена индексом. После перевода первой в `done` тот же ключ снова проходит (partial-индекс корректен).
- **C. Рефанд + идемпотентность** — PASS. Задача с битым `fal_request_id` → reconciler нашёл за ~55 c, пометил `failed`, вернул кредиты один раз, поставил `refunded=true`; второй цикл reconciler баланс не тронул.
- **D. Таймаут ≠ рефанд** — PASS (чтением кода): `POLL_TIMEOUT` не рефандит, не пере-сабмитит, оставляет `running` для reconciler.

## Движок задач — тип 'animate'

### Списание
1. Роут `POST /api/jobs` проверяет `free_{modelKey}` у юзера.
2. Если `free_wan > 0` (или `free_veo > 0`) — передаёт `freeColumn='free_wan'` в createJob, `costCredits=0`.
3. `createJob` в транзакции (BEGIN → SELECT FOR UPDATE → UPDATE free_column - 1 → INSERT job → COMMIT).
4. Если free нет — обычное списание кредитов в транзакции.
5. `_freeColumn` сохраняется в input задачи (для восстановления при сбое).

### Возврат при ошибке
- `failJob` проверяет `input._freeColumn`:
  - Если есть и валидный (`free_wan` / `free_veo`) — `UPDATE users SET free_X = free_X + 1`.
  - Иначе — возвращает `cost_credits` как обычно.
- Валидация: `['free_wan', 'free_veo'].includes(freeColumn)` — защита от SQL injection.

## Схема БД
Новые поля в `users`:
- `free_wan INTEGER DEFAULT 1` — бесплатные генерации Wan
- `free_veo INTEGER DEFAULT 1` — бесплатные генерации Veo

Новые поля в `generation_jobs` (фикс утечки + сид, все через `ALTER TABLE ... ADD COLUMN IF NOT EXISTS`):
- `seed BIGINT` — сид генерации (для воспроизводимости)
- `fal_request_id TEXT` — id запроса в очереди fal (для возобновления/сверки)
- `last_polled_at TIMESTAMPTZ` — отметка последнего опроса (для reconciler)
- `idempotency_key TEXT` — ключ дедупа
- `refunded BOOLEAN DEFAULT FALSE` — флаг идемпотентного возврата
- Индекс: `uniq_active_job` — partial UNIQUE `ON (idempotency_key) WHERE status IN ('pending','running') AND idempotency_key IS NOT NULL`

В `brief` (JSONB поле projects):
- Раньше: `{ topic, style, duration, selectedScenario, scenarios, scenes_media, voice }`
- Теперь: `{ source: 'upload', image_url, model, motion, video_url }`
- Старые поля не мигрированы, просто не читаются. Старые проекты останутся с устаревшим brief.

В `projects`:
- `result_url` — URL готового MP4 (заполняется при успехе задачи animate).
- `status` — ставится `'ready'` при завершении.

## Известные баги
**Не тестировалось живьём.** Возможные проблемы:
1. Endpoint'ы fal могут требовать дополнительные обязательные параметры — первый запрос покажет.
2. Формат ответа fal может не содержать `video.url` — код пробует 3 варианта, но если ни один не подойдёт — ошибка.
3. Публичный URL из нашего бакета может быть недоступен для fal (если фаерволл/регион).
4. `fal.config({ credentials })` вызывается при каждом запросе в `ensureConfig()` — не кешируется, потенциальный overhead (минимальный).
