# AI_PROVIDERS.md — VideoAI

> Обновлён 31.05.2026 после пивота. Прежняя версия описывала GigaChat-сценарии, Kandinsky, SpeechKit и FFmpeg — этот пайплайн демонтирован. Текущее ядро — оживление фото через fal.ai (Wan/Veo); Спринт B добавит генерацию картинок (Flux/Nano Banana).

Документ описывает единый интерфейс работы с AI-провайдерами. Цель — изолировать бизнес-логику от конкретного провайдера.

---

## Принципы

1. Каждый провайдер живёт в `server/providers/`
2. У каждого — одна точка входа с типизированным контрактом
3. Все вызовы асинхронные, возвращают `{ ok, data, error }` либо бросают типизированные ошибки
4. Стоимость в кредитах читается из env при старте (а не хардкодом)
5. AI-провайдеры вызываются только с бэкенда, никогда с фронта
6. Долгие операции (оживление) — всегда из контекста job, не блокируют HTTP

## Видео: fal.ai — оживление фото (image-to-video) ★ основное

**Файл:** `server/providers/falVideo.js`
**Клиент:** `@fal-ai/client`, очередь: `fal.queue.submit` → `fal.queue.status` (poll) → `fal.queue.result`.
**Авторизация:** `FAL_KEY` (единый ключ на все модели fal).

Две модели, **параметры задаются по-модельно — имена полей РАЗНЫЕ.** Финальный `input` логируется перед submit (`[fal] Submit input`).

### Kling 2.5 turbo — эконом (ТЕКУЩАЯ; заменила Wan 2.7)
Endpoint: `fal-ai/kling-video/v2.5-turbo/standard/image-to-video`

| Параметр | Значение | Примечание |
|---|---|---|
| `image_url` | публичный URL фото | из нашего S3 |
| `prompt` | текст движения | желательно без `rotation`; Kling и так трактует аккуратно |
| `duration` | `'5'` | СТРОКА (у Wan было числом) |
| `negative_prompt` | blur, distort, low quality, warped text, distorted lettering, deformed logo | целевой по тексту — ОК |
| `cfg_scale` | `0.5` | строгость следования промпту (рычаг управляемости вместо seed) |

- **`seed`:** в текущем Input ОТСУТСТВУЕТ. Проверить, поддерживает ли Kling 2.5 seed. Если нет — предсказуемость через `cfg_scale` + промпт; seed-механизм для Kling неактивен.
- **Нет** `enable_prompt_expansion` (у Kling такого параметра нет).
- **Аудио:** дорожки нет вообще (чище Wan).
- На выходе 716×1284, размер по аспекту фото.

**Стоимость:** `CREDITS_WAN` (дефолт 40 — имя осталось от Wan), факт **~$0.21/ролик** (5 × $0.042/сек).

> Wan 2.7 (`fal-ai/wan/v2.7/image-to-video`) — заменён. Был дороже ($0.50) и нестабилен: «лотерея» движения и плывущий текст. Оставлен здесь как история причины перехода.

| Параметр | Значение | Примечание |

**Стоимость:** `CREDITS_VEO` (дефолт 90), факт **~$1.20/ролик**.
**Проверено на проде (02.06.2026):** 8 сек, 720×1280, без аудио (`generate_audio:false` сработал), текст идеально цел, кинематографичный наезд — качество заметно выше Kling, апселл оправдан.

### Реализация внутри job
1. Задаём явный `seed`; `fal.queue.submit(endpoint, { input })` → **сразу сохраняем `fal_request_id`** (до поллинга)
2. Цикл `fal.queue.status` каждые ~5 сек, прокидываем `progress` в `generation_jobs`; таймаут ≥ 6 мин (Wan идёт 4-5 мин)
3. `fal.queue.result` → URL клипа у fal
4. Скачиваем и **перезаливаем в наш S3** (URL у fal временные)
5. Возвращаем `{ url, seed }` нашего бакета

> Контракт (ориентир): `export async function animate({ imageUrl, prompt, model, seed })` → `{ url, seed }`, где `model ∈ {'wan','veo'}` выбирает блок параметров.

### Защита от денежной утечки (критично)
fal списывает за **выполненный** запрос независимо от того, забрало ли приложение результат. Поэтому:
- **Дедуп:** `idempotency_key` + partial UNIQUE индекс; повторный клик/гонка не создаёт второй сабмит.
- **Возобновление, а не пере-сабмит:** при обрыве — дочитывать по сохранённому `fal_request_id`, не слать новый запрос.
- **Reconciler** (каждые 90 c) добирает «осиротевшие» задачи по `fal_request_id`: COMPLETED→S3→done, FAILED→refund. **404 от fal = terminal failure.**
- **Refund только при реальном FAILED**, идемпотентно (флаг `refunded`); по нашему таймауту — НЕ рефандить, отдать reconciler.
- Только `fal.queue.*` (submit/status/result по `request_id`), НЕ `fal.subscribe` (не возобновляется после обрыва).

## Картинки: fal.ai — Nano Banana 2 (Спринт B, реализовано и проверено живьём)

**Файл:** `server/providers/falImage.js`
**Эндпоинт:** `fal-ai/nano-banana-2`. **Цена факт: $0.08/картинка** (по счёту).

Параметры (по схеме fal):
| Параметр | Значение | Примечание |
|---|---|---|
| `prompt` | англ. строка | от GigaChat (`buildImagePrompt`) |
| `num_images` | `1` | пока одна |
| `seed` | int | поддерживается, задаём и сохраняем |
| `aspect_ratio` | `'3:4'` | под карточки маркетплейсов; видео потом наследует 3:4 |
| `output_format` | `'png'` | |
| `resolution` | `'1K'` | |

- Формат ответа: `{ images: [{ url, ... }] }`. `extractImageUrl` пробует 6 путей (на практике сработал первый — `data.images[0].url`).
- **COMPLETED без URL** → НЕ пере-сабмит (fal уже списал); дочитать по `fal_request_id`; если нет — `failed` + идемпотентный возврат кредитов/пробника.
- Идёт через тот же движок задач (тип `image`): дедуп, reconciler, возврат. Результат (URL картинки в S3) → во вход `animate`.
- **Важно для продукта:** генерирует иллюстрацию ПО ОПИСАНИЮ, а не реальный товар пользователя. Путь «генерация» — для тех, у кого нет фото; реальный товар идёт через «загрузить фото».
- Стоимость: `CREDITS_IMAGE` (дефолт 13); пробник `free_image`.

## Общая структура ответа провайдера

```javascript
// Успех
{ ok: true, data: { url: '...' }, credits_used: 40 }

// Ошибка
{ ok: false, error: { code: 'PROVIDER_ERROR', message: '...', retryable: true } }
```

**Коды ошибок:**
- `AUTH_ERROR` — не получили доступ (не повторяем)
- `RATE_LIMIT` — лимит провайдера (повтор через 30 сек)
- `INVALID_INPUT` — плохой вход (не повторяем)
- `PROVIDER_ERROR` — 5xx (повтор 1 раз)
- `TIMEOUT` — нет ответа вовремя (повтор 1 раз)

---

## Retry-логика (в `server/jobs.js`)

1. `error.retryable === true` → повтор 1 раз через 5 сек
2. Снова failed → задача failed, **идемпотентный возврат** кредитов/free-попытки (`failJob` смотрит `input._freeColumn` + флаг `refunded`, чтобы не вернуть дважды)
3. Логируем ошибку для админки

> Важно: возврат — только при реальном `FAILED` от fal. Наш таймаут поллинга ≠ failed: задача остаётся `running`, её добирает reconciler (см. «Защита от утечки»).

## Учёт стоимости

- Стоимость моделей — из env: `CREDITS_WAN` (40), `CREDITS_VEO` (90). Факт по счёту: Wan ~$0.50/ролик, Veo ~$1.20/ролик.
- Пробник: `free_wan` / `free_veo` (по 1 на старте) — если есть, кредиты не списываются, тратится попытка
- Списываем **до** вызова; при реальном failed — идемпотентно возвращаем кредиты/попытку; при успехе — остаётся списанным
- fal берёт деньги за выполненный запрос даже если результат не забран — отсюда reconciler и дедуп (см. выше)
